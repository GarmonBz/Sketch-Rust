A new interface for Sketch Rust

The program today is a pixel-for-pixel port of the browser app, which follows the ribbon, tool rail, area-code panel and status bar arrangement common to Apex-style sketch programs. This proposal keeps every feature and rebuilds how the screen is organised, named and styled.

I am not a lawyer, and I could not compare against Apex itself here. I worked from the reference screenshots in refs/ui-spec. A new layout, vocabulary and visual identity removes the look-and-feel resemblance. It does not settle questions about code, file formats or bundled data, which are listed at the end.

Renderings

Tablet and phone

The tablet is the main touch target. It is the size an appraiser can sketch on while walking a house, and it has room for the full layout. The same parts rearrange by window width, so the Android version is a layout of this design and not a second one. Nothing is removed on a smaller screen. It moves into a slide-over, a sheet or a menu.

Area types are fully editable

Living space floors get four distinct colours

Today the four living-space floors are four close shades of blue, which are hard to tell apart on a multi-storey sketch. The proposal keeps First Floor as it is and gives the other three their own hue. None of them repeats the greens used for building area, the purple for garages, the grey for basements or the amber for porches.

These are new defaults only. A sketch that was saved with its own type table keeps its colours, and so does a customised type library. Any of the four can still be changed in the editor above.

  • All 32 stay. First to Fourth Floor living area, First to Tenth Floor building area, Garage, Carport, Finished and Unfinished BSMT, the four porches, Patio, Wood Deck, Balcony, Pool, Shed, Storage, Land, Subject Site, Non-Calculated Area and Undefined Area.
  • Today you can create a type with every field, but an existing type only lets you change its name, colours and fill. Anything else means editing raw JSON.
  • Proposed: one form for code, name, description, group, multiplier, sign, whether it counts as living area, line colour, fill colour, fill style and opacity. Plus New, Duplicate, Delete, reorder, Import, Export and Restore defaults.
  • One rule kept: Undefined Area can be restyled but not deleted, because areas fall back to it when their type is deleted.
  • Each drawn area stays editable in the inspector: name, type, factor, sign, auto-subtract, deduct-from, attributes, fill and line style, label options, and its walls by handle or typed length.

The symbol library is fully editable

  • Already in the app: rename, move to a category, add to favourites, hide and restore, delete, delete or rename a category, merge duplicates, import from DXF.
  • To add: edit a symbol's properties (description, wall snapping, wall gap, end cap, units), edit its shape, make a symbol from whatever is selected in the sketch, duplicate, create an empty category, reorder, export the library, restore the original library.
  • Shape editing reuses the sketch's own drawing tools on a small canvas, so there is no second editor to learn.

Build order

  1. Tokens and fonts. Keep the three palettes in theme.rs, add the amber strip colour, bundle Barlow, drop the double-ink text pass that imitated Chrome's rendering.
  2. Flexible layout. The chrome is pinned at coordinates measured from a 1400×860 screenshot, and ribbon_tabs.rs is generated from that spec. The new shell uses normal iced rows and columns so it resizes properly.
  3. Size classes. Build each panel once and place it by window width: side panel when wide, slide-over when medium, bottom sheet when narrow. Tablet landscape and portrait are the two touch layouts to get right first. The phone follows from them. Test by resizing the desktop window, well before any Android work.
  4. Coverage checklist. Turn the 634-row inventory into a checklist that names each feature's new home, and keep it passing as the old chrome is removed.
  5. Top bar. Replaces titlebar.rs, ribbon.rs, ribbon_tabs.rs and backstage.rs. Every ribbon command moves to the menu or the existing command search.
  6. Tool tray. Replaces rail.rs.
  7. Ledger, inspector and Insert drawer. Split dock.rs into these three. The inspector also absorbs area_props.rs.
  8. Area chooser and tape strip. New on-drawing widgets over the existing area and keyboard-entry logic.
  9. Area type editor. One form over the existing type table, replacing the raw JSON editor and the two partial dialogs.
  10. Symbol editor. Property and shape editing on top of the existing library functions in symbol_edit.rs.
  11. Touch input. The number and direction pad, press-and-hold menus, pinch and two-finger pan, 48px minimum targets.
  12. Drawing controls and start screen. Replace statusbar.rs and the recent-files list.
  13. Dialogs, help text and tests. Restyle the dialogs, rewrite the guide with the new names, and update the 9,000-line e2e.rs suite, which presses controls at old positions.
  14. Remove the old reference material. Before distributing, delete refs/, the parity documents and the old chrome modules.

The chrome steps can each land behind a setting that switches between old and new chrome, so the program stays usable throughout. Drawing, geometry, file formats and exports in sketch-core are untouched.

Outside the interface

  • Source lineage. refs/ holds the original web app's code and markup. If any of that was derived from Apex material and not written independently, a new interface does not change that. This is the question to put to a lawyer.
  • Old builds in dist/. Versions 0.1.21 to 0.1.29 ship an APEX-COMPATIBILITY.md describing an AXF reader and writer, including encrypted payloads, and integration as an Apex replacement inside the host program. The current code refuses AXF, but those older builds and documents should not be distributed, and how that reader was written matters more than any screen layout.
  • Leftover identifiers. Saved areas still carry an apex.calculation attribute key in area_calc.rs and area_repair.rs. Renaming it, with a fallback that reads the old key, removes the name from files the program writes.
  • Default lists. The built-in area codes (GLA1, GBA1, GAR, BSMT) and the room-label list should be checked against their source. The terms themselves are industry standard. The exact list and order may not be.
  • Names. The window title still says Appraisal Sketch. The guide mentions Apex and AXF by name. Mentioning them factually is normally fine, but worth a review.
  • Already clear. AXF files are refused. The symbols are CC0 and the icons are MIT.
