# 02. Architecture

Facts in this file were read from the code on 2026-11-14 (version 0.1.34, branch
`codex/sketchie-format`). Line numbers drift. Search for the names.

## 1. What exists

- Workspace: `crates/sketch-core` (geometry, calculations, formats, symbols) and
  `crates/sketch-app` (the iced 0.14 desktop program).
- `crates/sketch-app/src/main.rs` (about 10,000 lines) holds:
  - `pub enum Message` (one flat enum, over 200 variants).
  - `pub struct App` (all state).
  - `App::update` and `App::update_inner` (all behaviour).
  - `App::view` (composition): a `column![titlebar, ribbon, workspace, statusbar]` under
    a `stack![...]` of about 40 overlay layers (dialogs, menus, toasts).
  - `App::subscription`, `program()`, `main()`.
- Classic chrome modules, each with a `view` or `layer` function that returns
  `Element<Message>`:

- Layout style of classic chrome: absolute. `theme::at(x, y, element)` pins elements at
  positions measured at 1400 x 860. Do not copy this style.
- State that views read: `self.view` (`view_state::View`: mode, zoom, pan, grid, snap,
  filters), `self.drawing` (lines, polygons, symbols, texts, hud, options, auto_post),
  `self.selection`, `self.pages`, `self.layers`, `self.area_codes` (`Vec<AreaCode>`),
  `self.symbols` (`Arc<Result<SymIndex, String>>`), `self.dock`, `self.workflow`,
  `self.undo`, `self.recent`, `self.disto`, `self.bg_image`, `self.computed`,
  `self.calcs_totals`, `self.window_size`.
- Tools are `view_state::Mode`: Select, DefineArea, Fence, Lasso, Pan, DrawExterior,
  DrawInterior, InsertVertex, Curve, Measure, ChainDim, ZoomFence, PlaceSymbol,
  PlaceShape, PlaceText.
- Touch: `sketch_canvas.rs` already tracks fingers and emits `Message::Pinch` for
  two-finger zoom and pan.
- Tests: `e2e.rs` (about 9,000 lines) runs the real program headlessly with
  `iced_test::Emulator` at 1400 x 860, driving it with `click "Text"`, `click (x, y)`,
  `type`, `expect "Text"`, and writes screenshots to `target/e2e/`. `tools/e2e.sh` runs
  them and compares screenshots with `refs/ui-spec/gallery/`.
- Persistence (`persist.rs`, per-user files): `area-codes.json`, `symbol-library.json`,
  `symbol-favorites.json`, `text-library-labels.json`, `default-options.json`.
  Window placement: `window_state.rs` (minimum window 800 x 560).

## 2. Principle: one behaviour layer, two shells

```
              +--------------------+
  input  -->  |  Message (shared)  |  -->  App::update (shared, unchanged)
              +--------------------+
                 ^             ^
     classic views             next views
  (titlebar, ribbon,        (ui::topbar, ui::tray,
   rail, dock, status)       ui::ledger, ...)
```

Both shells read the same `App` state and emit the same `Message` values. This is what
guarantees no feature is lost: a feature is "moved" when a next-shell control emits the
message its classic control emitted.

## 3. Shell switch

Add to `App`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum Shell { #[default] Classic, Next }
```

- Field `shell: Shell` on `App`.
- Chosen at boot: environment variable `SKETCH_UI=next` or `classic`; otherwise the
  persisted value in a new per-user file `ui-shell.json`; otherwise Classic. From P15 the
  default is Next and the switch is removed.
- `App::view` becomes:

```rust
fn view(&self) -> Element<'_, Message> {
    match self.shell {
        Shell::Classic => self.view_classic(), // the current body, renamed, untouched
        Shell::Next => ui::view(self),
    }
}
```

- The overlay stack (dialogs, toasts, pop-ups) is shared. Extract the part of the current
  `view` that builds the layers into `fn overlay_layers(&self) -> Vec<Element<Message>>`
  and use it from both shells. Layers that are positioned from classic coordinates
  (`backstage::layer`, `minimap::layer`, `undo_history`, `select_menu`, `popup_menu`
  anchors) need a Next variant or an anchor passed in; handle each in the phase that
  replaces its opener.
- Title: both `program().title(...)` and the classic title bar use "Appraisal Sketch".
  Next uses "Sketch Rust - <name>".
- Window: Next keeps `decorations: false` on Windows and draws its own controls in the
  top bar. Lower the minimum window size to 360 x 560 when Shell is Next so Compact can
  be tested on desktop.

## 6. Command registry

Today commands are scattered: the ribbon, the backstage, context menus, the palette
`CATALOG` and the shortcut table each list their own. The Next shell has one registry.

```rust
pub struct Command {
    pub id: &'static str,          // stable kebab-case id, reuse CATALOG ids where they exist
    pub label: &'static str,       // new vocabulary
    pub group: Group,              // File, Edit, View, Areas, Insert, Image, Tools, Help
    pub shortcut: &'static str,    // display only; real keys stay in input.rs
    pub enabled: fn(&App) -> bool,
    pub checked: Option<fn(&App) -> bool>,
    pub run: fn(&App) -> Message,
}
pub fn all() -> &'static [Command];
pub fn find(id: &str) -> Option<&'static Command>;
```

- `ui/menu.rs` renders the Menu from `all()` grouped by `group`.
- The command palette lists `all()` (replacing `CATALOG` in Next) so every command is
  searchable.
- `coverage.csv` references command ids. A unit test checks every id named in the CSV
  exists in the registry.
- The seven palette ids that the original left unwired already work in this port
  (`command_palette::action`). Keep them working.

## 7. Size class and density plumbing

- `App` already stores `window_size` and receives `Message::WindowResized`.
- `ui::layout::SizeClass::of(self.window_size.width)` is computed in `ui::view`.
  Thresholds: Wide >= 1100, Medium 700 to 1099, Compact < 700.
- `ui::view` composes:
  - Wide: `column![topbar, row![ledger, drawing_stack, inspector?]]`.
  - Medium: `column![topbar, pagebar, stack![drawing_stack, ledger_slide?, inspector_slide?]]`.
  - Compact: `column![topbar, pagebar, drawing_stack, toolbar, sheet_or_pad?]`.
  - `drawing_stack` is `stack![canvas, controls, tape, tray, pad?, drawer?]`.
- The canvas widget and its `SketchCanvas { .. }` construction are shared with classic.
  Extract the construction from the current `view` into `fn canvas_element(&self)`.
- Anything that converts window coordinates to canvas coordinates assumes the classic
  canvas origin (for example `minimap::CANVAS_ORIGIN = (41, 129)`, the dock drag drop
  test, context menu anchors). Add `fn canvas_origin(&self) -> Point` on `App` that
  returns the classic constant or the Next layout's origin, and route those uses through
  it. Search for `129.0`, `41.0`, `CANVAS_ORIGIN`, `TOP`, `dock.width()`.

## 8. Testing approach

- Keep `e2e.rs` as is. It runs Classic.
- Add `e2e_next.rs` with the same `Harness` (make the harness `pub(crate)` in a small
  `e2e_support.rs`). Boot with the shell forced to Next.
- Every Next test runs at four sizes: 1400 x 860 (Wide, Comfortable), 1280 x 800 (Wide,
  Touch), 800 x 1280 (Medium, Touch), 372 x 800 (Compact, Touch).
- Prefer `click "Label"` and `expect "Label"` over coordinates so tests survive layout
  changes.
- Screenshots go to `target/e2e-next/<name>-<size>.png`. They are for human review, not
  pixel comparison. There is no reference gallery for Next.
- Behaviour tests in `main.rs` `mod tests`, `management_tests.rs`,
  `area_repair_tests.rs` and all of `sketch-core` must keep passing unchanged, except
  the assertions on default colours touched in `05-area-types.md`.

## 9. Things that are easy to break

- **Drag from panels to the drawing** uses window-space pointer positions and the dock's
  width to decide whether the drop is over the canvas (`DockDragMove`, `DockDragRelease`,
  `update_area_drop_hint`). Route through `canvas_origin` and a new `canvas_rect`.
- **Focus and keys.** A focused text input swallows keys before the root `EventTap`.
  The palette and layer rename use raw `event::listen_with` subscriptions for Escape and
  arrows. New inputs that need Escape or arrows must do the same.
- **The chrome must stay the first child of the root stack** so widget state survives an
  overlay closing mid-click (see the comment in `view` about the backstage).
- **Mini map** takes a window screenshot and crops the canvas. Its crop rectangle must
  use `canvas_rect`.
- **Integration mode** (Appraise-It Pro, `appraise_it.rs`, `report_sketch.rs`) changes
  close behaviour and titles. Do not change `update`; only move its controls.
- **`--check-installation`** in `main()` calls `app.view()`. It must pass under both
  shells.
